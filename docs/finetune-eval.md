# FunctionGemma の評価の物差し（追加学習の担当向け）

最終更新: 2026-11-09。学習のやり方（データを足す・回数を変える・モデルを変える）は自由。**物差しはこのファイルと `backend/finetune/score.py` で固定**し、何度やり直しても同じ方法で比べる。

## 1. 何をできるようにするか
圏外の時、旅行者が慌てて話す一言（英語・中国語・韓国語・日本語）を、アプリの頼みごと（関数）に聞き分ける。避難先を選ぶのはアプリ（公式データ）で、モデルは選ばない。

| 関数 | 引数 | 例 |
|---|---|---|
| reselect | mobility = normal / slow / wheelchair | 別の場所は？／子どもが走れない／車いす |
| ask_floor | なし | 何階まで上がる？ |
| road_blocked | なし | 道がふさがっている |
| lost_family | なし | 家族とはぐれた |
| injured | なし | けがをした |
| when_to_return | なし | いつ戻っていい？ |
| repeat | なし | もう一度言って |
| other | なし | 関係ない言葉 |

## 2. 決まり
| 決まり | 理由 |
|---|---|
| `backend/finetune/data/test.jsonl`（400 件）は**学習に使わない・中身を見て学習データを寄せない** | 使うと覚えただけで点が上がる |
| 採点は `score.py` だけで行う。採点の仕方を変える時はチームで決めて、このファイルを直す | 毎回同じ物差しにする |
| 比べる相手は**キーワード方式**（`score.py` に入っている）。これより良くないなら AI を使う意味が無い | 単純な方法で足りるなら、そちらを使う |
| 学習データを足す時は、テストと別の言い方（別の指示）で作る | テストに寄せないため |
| 追加: **人が書いたテスト**（チームで 50 件ほど、実際にスマホの音声入力を通した文）を `test_human.jsonl` に作る | Gemini が作った文だけで測ると、Gemini の癖に合わせただけになる |

## 3. 指標と成功の線
| 指標 | 中身 | 成功の線 |
|---|---|---|
| 正答率（全体） | 関数の名前と引数が両方合った割合 | **90% 以上**、かつキーワード方式より上 |
| 頼みごとごと | 10 種類（reselect は引数ごと）それぞれの正答率 | どれも **85% 以上** |
| 言語ごと | en / zh / ko / ja それぞれ | どれも **85% 以上** |
| **危ない間違い** | 「走れない・車いす・けが・道がふさがった」を other か reselect(normal) にした割合 | **2% 以下** |
| 関係ない言葉で動いてしまう | 正解が other なのに、選び直しなどをした割合 | **3% 以下** |
| 形の崩れ | 出力から関数が読めなかった割合 | **1% 以下** |
| 速さ | タブレットでの 1 回の返事。遅いほうから 5% の値 | **3,000 ms 以内** |
| 大きさ | `.litertlm` のファイル | **300 MB 以下** |

**今のキーワード方式の点（2026-11-09）**: 全体 70.5%／一番低い頼みごと lost_family 50%／一番低い言語 ko 66%／危ない間違い 15%／関係ない言葉で動く 10%

## 4. 採点のしかた
1. Colab で、テストの 400 件に予測を出して `predictions.jsonl` に保存する（test.jsonl と同じ順・同じ行数）
   - 1 行 = `{"name": "reselect", "args": {"mobility": "slow"}}`。読めなかった時は `{"name": null, "args": {}}`
   - タブレットで測る時は `"latency_ms": 820` を足す
2. `backend/` で次を動かす
   ```
   python -X utf8 -m finetune.score finetune/data/test.jsonl predictions.jsonl
   ```
3. 出た表（キーワード方式と並ぶ）をそのまま報告する。全部「OK」なら成功

## 5. 進め方のすすめ
1. 学習の前の点を測る（ノートブックの 4 章）。**特に日本語**。公式の Mobile Actions のデータは英語が中心なので、日本語が低い可能性が高い
2. 学習用のデータに足すとよいもの: 関西弁・高齢者の言い回し・慌てた断片（「やばい 逃げる どこ」）・音声の聞き間違い（「避難所」→「非難所」など）。テストと同じ指示では作らない
3. 変換した `.litertlm` を、**アプリに入れる前に Google AI Edge Gallery の「Load Model」（Mobile Actions）でタブレットに読み込んで**、速さと答えを確かめる
4. 関数の説明（description）は短く保つ。入力の長さ（KV キャッシュ 1,024 トークン）を、関数の定義が食うため

## 6. 報告してほしいこと

- 間違えた例を 10 件ほど
