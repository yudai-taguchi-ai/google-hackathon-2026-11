# 確かめ方の種類分けと、デモ動画の流れ（2026-11-08）

## 1. 確かめ方の4種類
| 種類 | 何をするか | コード | かかる時間 |
|---|---|---|---|
| ① 調べればわかる | 公式資料・規約・データの説明を読む | 不要 | 数分〜30分。Claude Code が代わりにできる |
| ② 作らずに試せばわかる | 手元のデータで計算・照合する、既存のアプリ（AI Edge Gallery・Google マップ）で試す | 使い捨ての小さなスクリプトだけ | 30分〜2時間 |
| ③ 作って動かさないとわからない | 自分たちのアプリで実装し、実機で測る | 要る | 半日〜。一番危ないので最初に小さく作って確かめる |
| ④ 人・現地に聞く | 運営への質問、現地を歩く | 不要 | 返事待ち・移動 |

# 追記：オンライン前提＋オフラインへの切り替え（2026-11-08）

## チームの方針
- オンラインで動くことを前提にし、通信が落ちたらオフラインに切り替える設計にする
- Google 技術を見せることが大事。オンライン時は Navigation SDK をアプリ内で使う（Google マップに引き継ぐと、会話が途切れ、事前の地域データも引き継げないため）
- 「通信が残っている最初の数分で、いちばん良い案内をする」も強みにする
- デモはオンラインとオフラインの2つを撮り、切り替わる瞬間も見せる

## 通信はいつ落ちるか（調べた結果）
| 時期 | 起きること | 根拠 |
|---|---|---|
| 発災直後〜数日 | 混雑（輻輳）。通話は最大 70〜95% を規制。データ通信は規制なしか低い割合。通話量は平常の 50〜60 倍 | 総務省（東日本大震災） |
| 発災直後から | 回線の切断・設備の壊れで止まる基地局がある（能登の停波原因: 停電 68.5%・伝送路断 57.8%） | 総務省（能登） |
| 半日〜数日後 | 停電が続き予備のバッテリーが切れて、止まる基地局が一番多くなる。東日本大震災は翌日 3/12 が最多（ドコモ 17時・KDDI 20時・ソフトバンク 7時30分）。能登は 1/3〜1/4 が最多 | 各社・総務省 |
→ 津波の避難（数分〜数十分）の間は、混んでいてもデータ通信は残っていることが多いと考えられる。オンラインが主、オフラインは「混雑で遅い・近くの基地局が壊れた・データ通信を持たない旅行者・数時間後」の備え。

## 衛星で圏外は減っているか
- au Starlink Direct（2025〜）に加え、docomo Starlink Direct が 2026-04-27 開始（見出しのみ確認）、ソフトバンクも提供を発表 → 4 社とも衛星へ
- ただし国内の契約・対応機種が対象。訪日客の海外 SIM・eSIM が使えるかは見つからない（未確認）。衛星のデータ通信は対応アプリに限られる

## 「安全な道」を既存サービスはどうしているか
- ひろしま「避難所へGo!」・みえ防災ナビ・横浜市避難ナビ: 避難所への道順と、浸水想定などの地図の重ね表示。浸水想定区域を避ける経路探索は見つからなかった
- Google マップ: 浸水想定を避ける機能は無い
→ 「浸水想定区域を避けた道で、間に合う避難先へ」は既存に無い差になりうる
- 作り方: Routes API（徒歩）で道を出す → 浸水想定区域を通るか判定（V14）→ 通るなら経由地を足して出し直す → 経由地を Navigation SDK に渡す（V1）。徒歩で別の候補の道（alternative routes）が出るかは未確認。経由地があると別の候補は出ない制約あり

## 舞台を堺駅の前にした理由と、試作サーバーでの計算（2026-11-09）
- 理由: 大学から近く撮影しやすい。駅前にホテルがあり「宿で準備→翌朝駅前で揺れる」が自然。場面5で避難先が切り替わる（海遊館は最初から近い建物が選ばれ、切り替わらない）
- 計算（Routes API のキーなし＝直線距離×1.3。座標はおおよそ）。訓練電文の残り約20分の場合:
  - 通常 0.62m/秒 → スーパーホテル堺マリティマ（浸水想定区域の外）630m・約17分 … 間に合う
  - 「My child can't run」で 0.5m/秒 → 630m は約21分で間に合わない → エル・アバンダント堺（126m・約4分・3階以上）に切り替え
- 撮影の当日に、実際の GPS の位置で計算し直す（区域の境目では座標のずれで判定が変わる）
- 2つの避難先は堺市の津波避難ビル一覧（令和8年9月現在）と照らして一致（verification.md の V6）
